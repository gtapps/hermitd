# Refresh pending task decisions

This is a read-only evaluator procedure. The tick's `decision_items` are at most five task-id/generation pairs with an unspent delivery budget. Read each task's current decision and bounded Proposal, notes and cited evidence. A failed inventory read freezes this work. Never mutate a record, apply a change, send a notification or count delivery here.

Return one `refresh` entry for every supplied key: `{key,status:"open"|"partial"|"done",text:"<truthful plain question or evidence>"}`. Preserve the key exactly; an unverifiable item stays open with its original text. A done observation is evidence for the decider, never consent or closure. Report changed scope in the text so normal task intake can reopen consent. Input decisions resume their recorded procedure only after an answer is recorded.

The resident uses this text for the ask and sends it with `channel-send.ts .hermit --notice` and JSON `{"client":"From the agent: <change or question>. Waiting on you.","decision":{"task":"<task-id>","generation":<generation>}}`. The script routes admin decisions to the maintainer chat, else the home chat on every profile; other decisions use their own chat. It alone counts confirmed sends, at most two per generation. Failed or degraded sends consume none. No model writes delivery counts or acknowledges an unconfirmed relay. After two deliveries, waits remain in scoped briefs, status and dashboard without expiry or daily digest.
