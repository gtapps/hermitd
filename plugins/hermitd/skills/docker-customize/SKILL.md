# Docker Customize

Route each requested change to the surface below. `Dockerfile.hermit` and `docker-compose.hermit.yml` are plugin-owned: never hand-edit them. Their first line says `Generated by hermitd <version>` and names the four customization surfaces. Every host `up`, `restart` and `update` renders them from `.hermit/config.json`. An unconverted install keeps both files until Convert succeeds; a header from a newer plugin requires updating the host plugin.

Files sit on the project bind mount, so file preparation can run inside the container or on the host. Locate the current shell with `[ -f /.dockerenv ] || [ -f /run/.containerenv ] && echo container || echo host`. Rebuild, restart and Compose validation require the host's Docker CLI. Read `runtime_mode` from `.hermit/state/runtime.json` when deployment context is needed; `$TMUX` does not distinguish Docker from host tmux.

For personal and third-party skills, read [Personal and third-party skills in Docker](../../docs/creating-your-own-hermit.md#personal-and-third-party-skills-in-docker) and use the routes below for their dependencies.

## Apt packages

Add or remove packages through `/hermitd:hermit-settings docker`, which writes `docker.packages` using settings-edit and its protected-path prompt. Package names must match `^[a-z0-9][a-z0-9+\-.]+$`. Preserve packages the operator already chose.

Rebuild on the host with `hermitd restart --build`; from stopped, use `hermitd start --build`. The renderer reads the current list before the build. Removing a package from the list takes effect through that rebuild.

## Root and toolchain installs

Put root-only image setup in `<project-root>/docker-build.hermit-local.sh`. The image runs it with Bash as root after Claude Code and Bun are installed, then returns to `USER claude`. The file is optional and needs no executable bit. Preserve existing commands. Use `set -euo pipefail` so a failed install fails the build. For directories under `/home/claude`, use `install -d -o claude -g claude <path>` so the running agent can write them.

Run `bash -n` on the hook. Apply it through the same host rebuild command as apt packages. The plugin never writes this file.

## Boot-time shell

Put boot-time work in `<project-root>/docker-entrypoint.hermit-local.sh`. Persist files under `.claude.local/`. The managed entrypoint sources it twice:

- `HERMIT_ENTRY_PHASE=pre-boot`: after channel directories and env resolution, before plugin installation.
- `HERMIT_ENTRY_PHASE=pre-launch`: immediately before `hermitd-start`; side services and last-second overrides.

The hook runs as claude under `set -euo pipefail`. Anchor paths to `${PROJECT_DIR}`. Preserve existing content and guard optional commands with `|| true`. Create it with `#!/usr/bin/env bash` if absent; it is sourced and needs no executable bit. Check with `bash -n`, and run session-safe commands once now if needed. `hermitd restart` applies boot changes without rebuilding.

## Volumes, ports and env

Write `<project-root>/docker-compose.override.yml`, preserving existing operator content. The stack order is base, security overlay if present, then operator override if present; the operator override wins. Use `!override` for a replacement list and `!reset` to remove an inherited value, rather than assuming ordinary list merging removes base entries. Keep API keys in `.env`; keys exported only in the host shell do not reach the container.

Before each validation command on the host, select the files again:

```bash
COMPOSE_FILES=(-f docker-compose.hermit.yml)
[ ! -f docker-compose.security.yml ] || COMPOSE_FILES+=(-f docker-compose.security.yml)
[ ! -f docker-compose.override.yml ] || COMPOSE_FILES+=(-f docker-compose.override.yml)
docker compose "${COMPOSE_FILES[@]}" config -q
```

Use `hermitd restart` after validation, adding `--build` when the image changed. The plugin never writes the override.

## Convert

Convert existing Docker files only as a complete operation. If `Dockerfile.hermit` already has a first-line `Generated by hermitd <version>` header, stop and report **nothing to convert**.

1. Read both installed files and any existing build hook and override. Snapshot `Dockerfile.hermit` and `docker-compose.hermit.yml` to timestamped `.bak` copies under `.hermit/state/`. Keep those recovery copies through retries.
2. Run `.hermit/bin/hermitd-run settings-edit .hermit/config.json migrate browser-default-on`. Preserve an existing browser decision; the migration accounts for an operator-installed browser.
3. Set `docker.git_identity_mount` with settings-edit from the installed compose mount targeting `/home/claude/.gitconfig`. A custom mount source must also be retained as a replacement in the override.
4. Reconcile `docker.packages` with the installed project-package apt install stanza, preserving operator-selected packages. Write the reconciled list with settings-edit. Do not guess when a shell expression prevents identifying the packages; report those lines as unplaced.
5. Render a candidate to a scratch directory inside the project with `.hermit/bin/hermitd-run render-docker-templates <project-root> --to <scratch-dir>`. Check the verdict for errors. Keep the installed files untouched. An existing entrypoint is preserved by the renderer.
6. Diff installed and candidate files. Account for **every** changed or removed operator line:
   - Move custom root commands from the marked customization stanza and root work added after `USER claude` to a candidate `docker-build.hermit-local.sh`. Strip Dockerfile `RUN` syntax into shell commands and omit Dockerfile `USER` switches. Convert `mkdir` under `/home/claude` to `install -d -o claude -g claude`. Use the boot hook for work intended to run on every boot.
   - Move added volumes, env and ports to a candidate `docker-compose.override.yml`.
   - Preserve changed or removed base entries through `!override` or `!reset`. Validate those tags on the host with `docker compose ... config -q`, selecting the scratch base, existing security overlay if present, and candidate override in that order. If validation cannot run or fails, leave the installed files untouched and report the affected lines as unplaced.
   - Build hook and override candidates as **whole files**, incorporating any pre-existing operator content verbatim. Never append conversion commands to live files: retries after interruption must not duplicate them. If a conflict prevents retaining existing content verbatim, report it as unplaced. Check the candidate shell hooks with `bash -n`.
7. Only after every edit is placed and the required checks pass, write the complete candidate hook and override, then run `.hermit/bin/hermitd-run render-docker-templates <project-root> --convert` in place. Check its verdict. Otherwise leave both installed Docker files untouched, write no partial migration to operator files, and report **each unplaced line** in chat.

Report where each customization went and the snapshot paths. A retry starts from the installed files and existing operator surfaces and writes whole candidates, preserving previous operator content; the generated-header check makes a completed conversion a no-op. Ask the host to run the next `hermitd update` to regenerate again, rebuild and restart. An update-launched evolve leaves that build to the waiting host update. Tmux agents skip conversion.
