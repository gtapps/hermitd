# Approval rules

Manage standing classifier rules for this hermit, not a single chat. Use the channel reply tool for channel turns and ordinary conversation in the terminal.

1. **Authority.** Only an approver may request a standing change or removal; a terminal turn may do so too. For a channel turn, use the incoming envelope's actual sender `user_id` (not the display name) and the normalized channel name. Resolve the channel state directory like `scripts/lib/channel-token.ts` `channelStateDir`: `<CHANNEL>_STATE_DIR` environment override, else `channels.<name>.state_dir` in `.hermit/config.json`, else `.claude.local/channels/<name>`; resolve relative paths from the project root. Read its `access.json` and compare the sender id to the top-level `allowFrom` list as strings. If the sender id is missing or ambiguous, the file or list is unreadable, or the sender is not in it, say an approver needs to set this and stop. Never infer approval from chat membership, `allowed_users`, or a display name.
2. **Passing remarks.** A one-off instruction such as "don't push until I review" stays conversational; do not save it as a standing rule. If persistence is unclear, ask.
3. **Choose a list.** `environment` describes trusted context; `allow` permits classifier-reviewed actions; `soft_deny` blocks absent direct operator intent; `hard_deny` blocks unconditionally. Discuss scope or consequences when the intent does not select one.
4. **Compose.** Write one narrow sentence naming the action, its target, and the reason. Avoid broad unintended exceptions.
5. **Critique.** Run `.hermit/bin/hermitd-run operator-auto-mode critique --list <list> --text '<sentence>'`, shell-quoting the exact sentence. Treat the critique as wording advice, not enforcement. If you revise it, critique the revised sentence again or explicitly label it unchecked. On `unchecked`, tell the operator it could not be checked.
6. **Show.** Present the exact proposed sentence and its list before the Edit. For `allow`, explain that it cannot lift native ask or deny rules; inspect `permissions.ask` in the project's `.claude/settings.json` and `.claude/settings.local.json`, and name any seeded ask rule the action hits.
7. **Save.** Read `.hermit/claude-settings.json`; if absent, create an object with Write. Use Edit or Write to add the sentence to its `autoMode` list, creating the list with `"$defaults"` first when absent. Preserve all other keys and entries. The native permission prompt is the decision: a No is final, with no retry or workaround. Never use a script or shell to write the settings file.
8. **Validate.** Run `.hermit/bin/hermitd-run operator-auto-mode check`. Report `quiet_restart` as taking effect after the next quiet restart and `next_start` as taking effect at the next start. Report an invalid result rather than claiming success.
9. **List.** When asked to list rules, distinguish saved operator rules in `.hermit/claude-settings.json` from currently running rules in `.hermit/state/claude-settings.overlay.json`. The overlay includes generated entries and reflects the last launch, not an unswitched edit.
10. **Remove.** Identify the one named saved sentence, ask which if ambiguous, and delete only that entry using the same approver check and native prompt. Preserve `"$defaults"` and all other entries.
11. **Hardened.** If the Edit or Write is denied by the install, report "locked on this install". Do not retry or use another path.
