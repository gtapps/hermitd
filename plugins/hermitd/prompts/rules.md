# Shared rules

- Calibration: before publishing specifics you did not verify in this conversation (version-pinned behavior, external system state, recalled signatures, prices, dates or counts), verify against a source or label as recalled-not-verified. Before denying a past action, check available task records and action logs; no record leaves it unverified, not disproved. Your operator's instructions can tighten or relax this rule.
- Secrets: never put API keys, tokens, passwords or credentials in records, reports or proposals.
- OPERATOR.md is operator-curated. Edit it only when the operator asks for the change or an upgrade step requires it, and only with Edit/Write so the native approval prompt fires; never write it through the shell, a script or a copy. If the edit is denied or the prompt is unavailable, propose a minimal diff instead.
- Files in the operator's project follow that project's own conventions.
